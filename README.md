# Background
Our motivation for the project was improving the Google Nest Smart Thermometer. Our group thought of ways to broaden this idea to include more situations where being able to measure, display, and modify temperature to make the device smarter. Our goals were to record ranges of temperature, view data remotely, display on LCD, and manipulate as needed. To make the device smarter, we could implement this through a web app, where the user can login, view stored data, options to privacy, etc. Our reach goal was to simulate heating and cooling applications so as to hook up to a system that would be difficult for this course. We were recommended by Professor Bell to integrate our device with a weather API, which we attempted.

# Architecture
A Raspberry Pi Sense HAT is used on our output Pi to measure local temperature and humidity and provide the essential data for our system. A second Raspberry Pi, an output pi, is used in such a way that required the sense-hat to be removed in order to be setup for its proper function which is to display the real-time data onto the LCD screen. The output Pi could not use the sense HAT because we had to connect external devices to the pins underneath where the HAT usually sits. Hence, we needed to use an input Pi to measure the data on the frontend. 

The data collected locally on the input Pi is sent wirelessly via Wi-Fi to our cloud server. The data on the cloud server is then sent via Wi-Fi back down to our output Pi for displaying the data on the LCD screen. 

To host our data and do some of our calculations, we used Firebase and its ability to host a real-time database. This allowed all the data we collected to be stored without us worrying about storage space. We would also collect and display weather information about the entered location from a weather API, Open Weather. Through an integrated web application, we included the ability to view the current recorded temperature and to also be able to change the desired temperature. For authentication, we added a login screen to the web application, requiring a username and password to view your data. 

In addition to the privacy and security provided by Firebase hosting, our system provides a genuinely safe and private experience for its intended purpose. At this time, it is a locally hosted device where the information gathered, and input is stored and fetched within the database on one’s network with low vulnerabilities for data access from external entities. Thus, the primary and only person that should and has access to their own data, is simply the person providing it.  
# Outlook
Smart home technology is a competitive market. Control over temperature falls into this. In our project, we had to represent heating and cooling by using placeholders (LEDs). The aspiration is to be able to integrate into some heating/cooling system, but we were able to represent when the system needed change as desired by the users input through symbolic components. The cost of materials for this project was low as we were able to build this with supplies provided to us for the labs and previous classes. Including a weather API was a unique idea as many devices don’t include the outside temperature information. When integrated with the API, a user will have a more reliable, accurate, cost-effective, and efficient experience of using AC/heating. In terms of a typical thermostat, this project is an upgrade as it is a smart device as it makes the consumers life easier. It has remote access through the web app and simplifies the process of changing temperature which is a simple design in the app. Compared to a Google Nest, it requires more hardware and space but functions similarly.  

The system architecture and technology that we decided to use for our sensing component ended up being one of the two Raspberry Pi’s provided from each group. To use it as an input, we kept the SENSEHAT attachment on one of the Pi’s and transmitted the data over Wi-Fi to our database. The second Pi would act as the output, pulling data from the database, and doing a few different things based on what it received and what it calculated. And the website application actively reads from the database and sensors and determines how to provide feedback into our system to properly update the behavior of our components apart from displaying real-time information.  

Some issues we encountered while designing this project were learning how to connect and interact with the hardware from the Pi’s, learning how to properly use JSON objects between different code languages, front-end code and design, and how to keep our input Pi from overheating. Our way of getting around these problems was to do some research on the topics, and slowly make progress towards figuring them out until it all came together. From these issues, we learned more about how our hardware worked and integrating multiple programming languages.
